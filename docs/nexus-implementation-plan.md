# CampusClaw Nexus 实施与验收

需求来源：用户提供的 CampusClaw Nexus Project Proposal。该版本在课程 Flask 项目内升级，复用切片、Embedding、Skill 文件解析和认证原则。原课程数据库和上传文件保留；Nexus 使用独立 PostgreSQL 数据库及 Redis 队列。

## 实施顺序

1. SQLAlchemy/Alembic、PostgreSQL/pgvector、JWT/RBAC、审计与安全的旧数据迁移。
2. 材料版本、异步索引、混合检索与引用快照。
3. LangGraph 会话、三项 Skill、MCP SDK 工具与二次鉴权。
4. 知识缺口归并、教师审核及索引成功后的回补确认。
5. 按人发卷、冻结、异步批改、教师复核与错题。
6. 程序聚合周报、AI 解读、教师发布。
7. Vue 双端、端到端验证、隔离 Docker 部署。
8. 根据验证记录整理简历条目，不使用计划比例或未测指标作为完成情况。

## 部署约束

用户服务器已有网站。仅部署独立 Compose 项目 campusclaw-nexus，使用独立网络、数据卷与经检查的空闲端口。不得覆盖旧站配置、停止已有容器、改写旧数据库或清空原文件。公网 HTTPS 在不影响已有站点的前提下配置；没有域名或未完成证书验证时如实记录。

用户后续确定：先使用 IP:8088，HTTPS 稍后配置，本轮不修改原站 80/443。

## 验收路径

- A/B 班 API 与 MCP 资源权限；学生写教师接口 403。
- 索引失败时旧材料仍生效；新版本成功后原子切换；历史引用保持快照。
- 无证据拒答、创建班内候选缺口、教师回补、Worker 完成、重问命中。
- 两名学生不同实例；答案仅服务端；截止/冻结/交换答案/单人失败隔离。
- 批改结构化结果校验；保留 AI 原分、教师最终分；失败任务可重试。
- 周报数字来自程序事实；样本不足不推断趋势；草稿对学生不可见。
- MCP 调用 ID 与模型 tool 消息一致；未知工具、跨班资源及异常有审计。
